Primary project · case study on this page

ethStable Coin Simulator

  • Problem — AI can explain financial scenarios, but must not invent or alter authoritative numbers.
  • Architecture — Java/Spring owns BigDecimal simulation, read-only AI tools, numeric validation, and deterministic fallback.
  • Outcome — The UI renders backend-provided values while AI narration remains guarded, provenance-backed, and non-authoritative.
  1. 01 Deterministic logic stays outside the model
  2. 02 AI output is guarded and non-authoritative
  3. 03 Frontend renders backend-provided values only
  4. 04 Guardrails, precision, and fallbacks are covered by automated tests
  • Verification — 80+ Java test classes plus frontend unit/e2e coverage, including dedicated suites for PromptInjectionGuard, SecretRedactionService, NumericAuthorityValidator, GuardedToolCallingManager, adversarial regression corpus, BigDecimal/chart contracts, and agent fallback paths.

Engineering decisions

Why the architecture is shaped this way

  • Java owns financial math — avoids model-side or client-side numeric authority.
  • Validated AI path — narration is optional and must pass guardrails before it reaches the UI.
  • Deterministic fallback — model failure or validation failure does not break the core workflow.
  • Regression-first guardrails — unsafe prompts, tool abuse, and numeric hallucination become tests.
